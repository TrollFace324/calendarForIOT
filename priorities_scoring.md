# Приоритеты и оценка вариантов расписания

Этот документ задаёт предлагаемую логику следующей версии планировщика. Текущий код в `app/Program.cs` поддерживает только четыре общих критерия и **пока не реализует** описанную здесь оценку дисциплин, групп и окон. Документ нужен для согласования поведения перед изменением кода.

## 1. Что выбирает студент

Студент самостоятельно расставляет критерии по важности. Начальный порядок можно показать как пример, но после сохранения используется его порядок:

1. Желаемая дисциплина в блоке выбора.
2. Преподаватель конкретной дисциплины.
3. Свободная суббота.
4. Предпочтительная группа.
5. Другие нежелательные дни недели.
6. Окна между парами.
7. Число учебных дней.
8. Начало и конец учебного дня.

«Предпочтительная группа» видна всегда. Студент может оставить все группы без оценки. Для каждого критерия есть режим «Не учитывать». Приоритеты по преподавателям и группам задаются отдельно для каждой дисциплины. Суббота имеет свой критерий, остальные дни настраиваются независимо.

В блоке Modeus студент может оценить несколько альтернативных дисциплин одинаково. Если нужно выбрать одну, планировщик строит отдельные расписания с каждой из них. Результат сравнивается целиком. По желанию студента показывается лучший вариант для каждой отмеченной дисциплины, даже если один из них ниже в общем рейтинге.

## 2. Что является одним вариантом

Вариант расписания содержит требуемое число дисциплин из каждого блока и по одному допустимому комплекту занятий для каждой выбранной дисциплины. Комплект может состоять из нескольких связанных групп и нескольких пар в разные дни или недели. Если Modeus закрепил группу на весь период, она входит в комплект без выбора.

Каждая пара описывается датой либо правилом повторения, временем начала и конца, дисциплиной, группой и преподавателями. Пары числителя и знаменателя сравниваются по фактической неделе. Если известны даты полусеместров, оценка считается по всем датам семестра. Если дат нет, используется цикл из двух недель с пометкой о приближении.

Пара с неизвестным временем не считается свободным интервалом. Расписание с таким вариантом остаётся неполным и не попадает в итоговый рейтинг до уточнения времени.

## 3. Жёсткие условия

До оценки исключаются варианты, в которых:

- нарушено требуемое число дисциплин в блоке выбора;
- отсутствует обязательная дисциплина или закреплённый комплект;
- выбрана группа, помеченная недоступной или исключённой студентом;
- две пары пересекаются в один день одной недели;
- пара пересекается с личным временем, которое студент запретил занимать;
- есть хотя бы одно окно, когда выбран режим «Окон быть не должно».

Если из-за запрета не осталось расписаний, приложение показывает причину и предлагает изменить соответствующую настройку. Оно не снимает запрет автоматически.

## 4. Вклад пар в оценку

Для каждого допустимого расписания строится **вектор показателей**. Сначала показатели начисляются отдельным парам и выбранным комплектам, затем суммируются по всему расписанию. Вектор переставляется согласно порядку критериев студента. Два расписания сравниваются по первому показателю, в котором они различаются. Это позволяет складывать оценки пар и при этом сохранять правило «преподаватель выше субботы», если студент так его выставил.

| Критерий | Вклад в расписание | Когда начислять |
| --- | --- | --- |
| Дисциплина | Предпочтение выбранной дисциплины в своём блоке | Один раз за выбранную дисциплину, а не за каждую её пару |
| Преподаватель | Лучшее предпочтение среди преподавателей данного комплекта по этой дисциплине | Один раз за комплект дисциплины, чтобы частые пары не умножали оценку |
| Предпочтительная группа | Оценка выбранной группы, если студент её задал | Один раз за группу; отсутствие оценки равно нейтральной оценке |
| Свободная суббота | Занятая суббота и число пар в ней | Первой паре субботы начисляется один занятый день; каждой паре — один счётчик пар |
| Другие нежелательные дни | Занятый нежелательный день и число пар в нём | Аналогично субботе, отдельно по выбранным дням |
| Окна | Длительность каждого окна в минутах | Окно привязывается к следующей паре того же дня и недели |
| Число учебных дней | Один занятый день | Начисляется первой паре каждого дня и недели |
| Начало и конец дня | Минуты за границами желательного диапазона | Раннее начало приписывается первой паре, позднее окончание — последней |

Такое распределение даёт один и тот же итог независимо от порядка обхода пар. Оно также не поощряет дисциплину только потому, что у неё больше занятий.

### Оценки дисциплин, преподавателей и групп

Для предпочтения используются уровни «очень хочу», «желательно», «нейтрально», «нежелательно». Несколько дисциплин одного уровня равны по критерию выбора дисциплины. Если у комплекта несколько преподавателей, берётся **лучший** из них. Например, «очень хочу» вместе с «нежелательно» дают оценку «очень хочу». Исключение конкретного комплекта задаётся отдельным жёстким запретом.

Чтобы большое число слабых предпочтений не перевесило одно сильное, для дисциплин и преподавателей суммируется не произвольное число баллов, а количество попаданий в каждый уровень: сначала количество «очень хочу», затем «желательно», затем меньшее количество «нежелательно». Для групп применяется то же правило только к явно оценённым группам. Если пользователь хочет, чтобы один сильный выбор гарантированно превосходил несколько слабых, эта схема это обеспечивает.

### Суббота и другие дни

Сначала сравнивается число **занятых суббот** за расчётный период. При равенстве сравнивается число субботних пар. Для других нежелательных дней применяется та же пара показателей. День, оставленный без отметки, не влияет на критерий.

### Окна

Окно — промежуток **не менее 90 минут** между концом одной пары и началом следующей в тот же день. Время до первой и после последней пары не учитывается. Промежутки меньше 90 минут не являются окнами.

Студент выбирает один из режимов:

- **Не важно** — окна не участвуют в оценке.
- **Лучше без окон** — суммируются полные длительности всех окон в минутах; меньшее значение лучше. При равенстве минут меньшее число окон лучше.
- **Окон быть не должно** — расписание с хотя бы одним окном исключается до оценки остальных критериев.

Например, расписание с одним окном 180 минут хуже расписания с одним окном 90 минут при режиме «Лучше без окон». При строгом запрете исключаются оба. Длительность вычисляется после объединения всех выбранных пар, поскольку окно появляется между двумя занятиями, которые могут относиться к разным дисциплинам.

## 5. Как сравнивать итоговые расписания

После сложения вкладов сравнение идёт в порядке, который выставил студент. Каждый критерий может содержать несколько показателей в фиксированном внутреннем порядке. Например, «свободная суббота» сравнивает занятые субботы, затем число пар; «окна» сравнивают минуты, затем число окон.

Пример порядка: **преподаватели → свободная суббота → окна**. Вариант А содержит желанного преподавателя и субботнюю пару. Вариант Б содержит нейтрального преподавателя и свободную субботу. Выигрывает А, поскольку различие по преподавателям решает сравнение раньше субботы. Если преподаватели равны, сравнение переходит к субботе.

Если две дисциплины в одном блоке одинаково желанны, критерий выбора дисциплины даёт ничью. Победитель определяется следующими критериями уже для полных расписаний с каждой дисциплиной. При полном равенстве показателей варианты остаются равноценными; для устойчивого порядка вывода их можно сортировать по ID, не объявляя один качественно лучше другого.

## 6. Запасные варианты и объяснение

Показываются лучший вариант в целом и альтернативы, отличающиеся хотя бы одной дисциплиной или группой. Для отмеченных студентом равнозначных дисциплин можно дополнительно показать лучший вариант с каждой. Карточка варианта указывает выбранных преподавателей, занятые субботы, суммарные минуты окон и конкретные замены относительно первого варианта.

Планировщик поясняет, какой **первый различающийся критерий** определил порядок двух вариантов. Так студент видит, почему, например, расписание с субботой оказалось выше расписания без неё.

## 7. Последовательность реализации

1. Отделить в модели блок выбора дисциплины, комплект групп и отдельную пару. Сохранить правила «выбрать одну / несколько» из Modeus.
2. Добавить настройки студента: порядок критериев, оценки дисциплин, преподавателей и групп, дни недели, режим окон, диапазон времени.
3. Генерировать допустимые варианты и отсеивать жёсткие нарушения. Для равнозначных дисциплин строить варианты с каждой.
4. Считать вектор по всем парам и комплектам, суммировать его и сравнивать по пользовательскому порядку.
5. Вывести лучший результат, запасные варианты и объяснение первого различия. Проверить на сценариях с желанным преподавателем в субботу, окнами 89/90/180 минут и двумя равнозначными дисциплинами.
